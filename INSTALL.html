Was gleich passiert

Vier Abschnitte. Der erste läuft an deinem Mac, der zweite am Server mit Bildschirm, der dritte über SSH, der vierte im Router und beim DNS-Anbieter.

AbschnittWoWas dabei herauskommtDauer

04–07Server, mit MonitorUbuntu läuft, SSH offen, Platte richtig aufgeteilt25 min
08–10SSH vom MacDas ganze SaaS installiert und gestartet20 min
11–14DNS, Router, BrowserAus dem Internet erreichbar, erster Server läuft15 min
Headless heißt hier: ab Schritt 08 nie wieder ein Bildschirm. Für die Installation selbst brauchst du einmal Monitor und Tastatur — du musst ins BIOS und durch den Installer. Danach kannst du beides abziehen; Ubuntu Server hat ohnehin keine Oberfläche. Willst du auch die Installation ohne Bildschirm fahren, steht der Weg ganz unten unter Wenn es klemmt. Für das erste Mal rate ich davon ab: Ein blinder Installationslauf sagt dir nicht, woran er gescheitert ist.
Abschnitt 1

Am Mac vorbereiten

Drei Schritte, danach ist der Server dran.
01

Ubuntu Server holen

Ubuntu Server 24.04 LTS, die Variante ohne Desktop. Nicht Ubuntu Desktop, nicht 25.10 — 24.04 ist bis 2029 versorgt, und der ZFS-Stack darauf ist lange durchgeschüttelt.

Auf ubuntu.com/download/server die Datei ubuntu-24.04.x-live-server-amd64.iso laden, rund 2,5 GB.

Nicht die ARM-Variante nehmen. Dein Mac ist vermutlich ein Apple Silicon, die Download-Seite bietet deshalb womöglich arm64 an. Der Server hat einen Intel-Prozessor und braucht amd64. Steht im Dateinamen.
02

USB-Stick schreiben

Der bequeme Weg ist balenaEtcher: ISO wählen, Stick wählen, schreiben. Über das Terminal geht es auch:

# Stick einstecken, dann seine Nummer suchen
diskutil list
# Die richtige Zeile erkennst du an der Größe. Nimm den Eintrag
# /dev/diskN — nicht /dev/diskNs1.

diskutil unmountDisk /dev/diskN

# rdiskN statt diskN ist deutlich schneller
sudo dd if=~/Downloads/ubuntu-24.04.3-live-server-amd64.iso \
        of=/dev/rdiskN bs=4m status=progress

diskutil eject /dev/diskN
dd fragt nicht nach. Eine falsche Nummer schreibt über deine interne Platte oder eine angesteckte Festplatte. diskutil list zweimal lesen und die Größe abgleichen, bevor du Enter drückst. Im Zweifel Etcher nehmen — das zeigt dir den Namen des Sticks im Klartext an.
03

SSH-Schlüssel bei GitHub hinterlegen

Ein Umweg, der sich sofort auszahlt: Der Ubuntu-Installer kann öffentliche Schlüssel direkt von GitHub laden. Damit kommst du nach dem ersten Neustart ohne Passwort auf den Server — und musst nie ein Passwort über das Netz schicken.

# Hast du schon einen Schlüssel? Dann steht hier etwas.
ls ~/.ssh/id_ed25519.pub

# Falls nicht, einen anlegen. Passphrase vergeben, der Schlüssel
# liegt danach unverschlüsselt auf der Platte.
ssh-keygen -t ed25519 -C "mac"

# Öffentlichen Teil in die Zwischenablage
pbcopy < ~/.ssh/id_ed25519.pub

Dann auf github.com/settings/keys → New SSH key → einfügen → speichern. Titel egal.

Warum über GitHub und nicht per Passwort? Der Installer fragt sonst nur nach einem Passwort, und dieses Passwort ist dann das Einzige, was zwischen dem Internet und deinem Server steht. Über den Schlüssel entfällt es komplett: Das Setup-Skript schaltet die Passwort-Anmeldung in Schritt 10 ab — aber nur, wenn es einen hinterlegten Schlüssel findet. Ohne Schlüssel lässt es sie an, sonst sperrst du dich selbst aus.
Abschnitt 2

Installieren, mit Bildschirm

Monitor und Tastatur an den Server. Das letzte Mal.
04

Vom Stick booten

  1. Netzwerkkabel einstecken. Kabel, nicht WLAN — der Installer richtet WLAN zwar ein, aber ein Server, dessen Erreichbarkeit an einer Funkverbindung hängt, ist keine gute Idee.
  2. Stick einstecken, einschalten, sofort die Setup-Taste drücken: meist Entf, bei manchen Boards F2. Die Meldung steht kurz im Startbild.
  3. Im BIOS: Boot-Reihenfolge auf den USB-Stick, oder direkt das Boot-Menü nehmen (F11 oder F12).
  4. Speichern und neu starten. Im Ubuntu-Startmenü Try or Install Ubuntu Server wählen.
Secure Boot kann anbleiben. Ubuntu liefert das ZFS-Modul signiert mit, es lädt auch bei aktiviertem Secure Boot. Du musst im BIOS nichts abschalten.

06

Die Platte aufteilen

Du hast eine SSD, und sie muss beides tragen: das System und den ZFS-Pool für die Weltdaten. Deshalb legst du nur zwei Partitionen an und lässt den Rest frei — den holt sich ZFS später.

PartitionGrößeFormatEinhängepunkt
11 GBEFI System Partition/boot/efi
2120 GBext4/
—Rest, ca. 810 GBfrei lassen

Klick für Klick

  1. Unter AVAILABLE DEVICES steht deine SSD. Falls dort schon Partitionen hängen: bei der Platte Reformat wählen, das räumt sie leer.
  2. Auf der Platte Enter → Use As Boot Device. Damit legt der Installer die 1-GB-EFI-Partition selbst an. Du musst sie nicht von Hand bauen.
  3. Jetzt steht unter der Platte eine Zeile free space. Darauf Enter → Add GPT Partition.
  4. Size: 120G eintippen. Format: ext4. Mount: /. Dann Create.
  5. Unter der Platte bleibt eine Zeile free space mit rund 810 G stehen. Die rührst du nicht an.
  6. Done → der Installer warnt, dass die Platte überschrieben wird → Continue.
Wenn am Ende kein free space übrig ist, stimmt etwas nicht. Dann hast du entweder den geführten Weg statt Custom storage layout erwischt, oder bei der Größe die Einheit vergessen und 120 statt 120G eingetippt. Geh zurück und prüfe es — nachher fehlt der Platz für den Pool, und dann hilft nur noch verkleinern oder neu installieren.
Warum kein LVM und keine Verschlüsselung? Beides bringt hier nichts ein und kostet. LVM ist eine Schicht mehr zwischen ZFS und der Platte. Verschlüsselung verlangt bei jedem Neustart eine Eingabe — auf einem Rechner ohne Bildschirm heißt das, dass er nach jedem Stromausfall stehen bleibt, bis du hingehst.

Abschnitt 3

Ab hier ohne Bildschirm

Alles Weitere läuft im Terminal deines Macs.
08

Erste Verbindung

ssh DEINBENUTZER@192.168.1.42

# Beim ersten Mal fragt SSH nach dem Fingerabdruck des Hosts — mit
# yes bestätigen. Nach einem Passwort sollte er nicht fragen.

# Angekommen? Dann erst mal alles aktualisieren.
sudo apt update && sudo apt full-upgrade -y
sudo reboot

Nach dem Neustart wieder verbinden. Kurze Kontrolle, dass die Platte so aussieht wie geplant:

lsblk
# Erwartet: nvme0n1 mit p1 (1G, /boot/efi) und p2 (120G, /).
# Der Rest der Platte taucht hier nicht auf — das ist richtig so,
# unpartitionierter Platz hat keinen Namen.

sudo sgdisk -p /dev/nvme0n1 | grep "free space"
# Erwartet: rund 1,7 Milliarden Sektoren, also ~810 GiB.
Fragt er nach einem Passwort, hat der Schlüssel nicht geklappt. Dann hat der Installer den Import übersprungen. Kein Drama: Mit dem Passwort anmelden und den Schlüssel nachreichen mit ssh-copy-id DEINBENUTZER@192.168.1.42 vom Mac aus. Danach noch einmal verbinden und prüfen, dass es ohne Passwort geht — bevor du Schritt 10 startest. Das Skript schaltet die Passwort-Anmeldung sonst ab, während du noch keinen Schlüssel hast.
09

Feste Adresse im Router

Der Server hat seine IP per DHCP bekommen, und die kann sich nach einem Stromausfall ändern. Dann zeigt die Portweiterleitung aus Schritt 12 plötzlich auf den Drucker.

# MAC-Adresse ablesen (die Zeile "link/ether")
ip link show | grep -A1 "state UP"

Im Router unter DHCP oder Netzwerk → Geräte die Reservierung setzen: diese MAC bekommt immer diese IP. Bei einer FRITZ!Box heißt der Haken „Diesem Netzwerkgerät immer die gleiche IPv4-Adresse zuweisen".

Warum Reservierung und keine statische Konfiguration? Eine im Server fest eingetragene IP funktioniert genauso — bis jemand den Router tauscht oder das Subnetz ändert. Dann ist die Maschine ohne Bildschirm nicht mehr erreichbar. Die Reservierung liegt an der Stelle, an der ohnehin alle Adressen verwaltet werden.
10

Ein Skript, siebzehn Schritte, etwa 15 Minuten. Es holt sich alles Weitere selbst — du brauchst das Repo vorher nicht zu klonen.

# Erst ansehen, dann ausführen. Immer, bei jedem Skript aus dem Netz.

Abschnitt 4

Ins Internet

Zwei DNS-Einträge, drei Ports, dann der erste Server.
11

DNS-Einträge

# Öffentliche IP des Anschlusses herausfinden
curl -fsS https://api.ipify.org; echo

Beim Anbieter von neuhauser.app zwei Einträge anlegen:

NameTypZielWofür
panelAdeine öffentliche IPDas Panel im Browser
*.mcAdieselbe IPAlle Server-Adressen auf einmal

Der Stern ist kein Tippfehler. Er sorgt dafür, dass jeder neue Server sofort erreichbar ist, ohne dass du für ihn einen Eintrag anlegst — welcher Container gemeint ist, entscheidet der Router auf dem Host anhand des Hostnamens im Minecraft-Handshake.

Wechselt deine öffentliche IP, zeigen beide Einträge ins Leere. Bei Privatanschlüssen ist das die Regel, meist nach jeder Zwangstrennung. Dagegen hilft DynDNS. Router können das oft nur für einen einzelnen Namen; für *.mc braucht es in der Regel einen kleinen Dienst auf dem Host, der die API deines DNS-Anbieters bedient. Das ist der eine Punkt, den ich noch nicht für dich erledigt habe — sag Bescheid, dann bauen wir ihn.
Vorher prüfen: Hast du überhaupt eine eigene IPv4? Bei DS-Lite — verbreitet bei Kabelanschlüssen — teilen sich viele Kunden eine Adresse, und Portweiterleitung funktioniert für IPv4 gar nicht. Erkennbar daran, dass die WAN-Adresse im Router aus 100.64.0.0/10 stammt oder dass dort gar keine IPv4 auftaucht. Vergleich auch die Ausgabe von curl api.ipify.org mit dem, was der Router als WAN-IP anzeigt: Sind die verschieden, sitzt du hinter einem Provider-NAT. Dann bleiben IPv6 mit AAAA-Einträgen oder ein Tunnel über einen kleinen VPS.
12

Portweiterleitung

Genau drei Ports auf die feste IP aus Schritt 09.

PortProtokollWofür
25565TCPMinecraft, alle Server über einen PortPflicht
443TCPDas PanelPflicht
80TCPWeiterleitung auf HTTPS, ACME-Prüfungempfohlen
Niemals weiterleiten: 22, 5432, 6379, 8080, 8787, 25575. Diese Dienste hören bewusst nur auf 127.0.0.1. Besonders 8787: Dort sitzt der Agent, und der hält den Docker-Socket. Eine Weiterleitung dorthin gäbe jedem im Internet Root auf deinem Rechner. Und 22 brauchst du nicht — für SSH von außen nimm ein VPN, kein offenes Tor.

Nach ein paar Minuten prüfen, ob das Zertifikat da ist:

curl -fsSI https://panel.neuhauser.app | head -1
# Erwartet: HTTP/2 200

# Falls nicht, Caddy fragen, woran es lag:
cd /opt/mc-saas/app/deploy && sudo docker compose -f docker-compose.prod.yml logs caddy | tail -30
13

Erster Admin

Im Browser auf https://panel.neuhauser.app registrieren. Der Bestätigungslink wird noch nicht per Mail verschickt, sondern steht im Log:

sudo journalctl -u mc-panel -f
# Registrieren, dann erscheint hier die Zeile mit dem Link.
# Kopieren, im Browser öffnen, fertig bestätigt.

Danach zum Admin machen — bewusst über die Shell und nicht über das Panel, sonst wäre die Admin-Rolle über die Anwendung selbst erreichbar:

cd /opt/mc-saas/app
sudo -u mcpanel node scripts/promote-admin.ts DEINE@MAIL

Neu anmelden, dann steht /admin offen.

14

Erster Server

  1. Unter /admin/plans stehen die Standardtarife aus dem Seed. Die Liste zeigt pro Tarif, wie oft er noch auf die Maschine passt.
  2. Unter /servers/new einen Server anlegen: Name, Adresse, Tarif, Software, Version.
  3. Warten, bis der Zustand auf läuft springt. Beim ersten Mal dauert es länger — das Container-Image wird geladen und die Welt erzeugt.
  4. Im Minecraft-Client verbinden: deinname.mc.neuhauser.app, ohne Portangabe.
Von innen klappt es oft nicht sofort. Viele Router leiten eine Anfrage aus dem eigenen Netz an die eigene öffentliche IP nicht zurück ins Netz — das heißt NAT-Hairpinning und fehlt gern. Von außen funktioniert es trotzdem. Zum Testen entweder das Handy im Mobilfunknetz nehmen oder im Client vorübergehend die interne Adresse eintragen.

Betrieb

systemctl status mc-agent mc-panel
journalctl -u mc-agent -f

cd /opt/mc-saas/app/deploy && sudo docker compose -f docker-compose.prod.yml ps

# Nach jedem Umbau: außer mc-router darf nirgends 0.0.0.0 stehen.
# Docker schreibt seine iptables-Regeln an der Firewall vorbei.
sudo docker ps --format '{{.Names}} {{.Ports}}'

# Pool im Blick behalten. Über 85 % wird ZFS spürbar langsam.
zpool list
zfs list -o name,used,quota

# Aktualisieren auf einen neueren Stand: derselbe Befehl wie beim ersten Mal.
# Nach der Domain fragt er nicht noch einmal, die liest er aus der .env.
sudo bash ~/setup.sh
Nicht von Hand bauen. pnpm kommt von corepack, und corepack legt seinen Cache unter $HOME an — für die Dienstkonten ist das /opt/mc-saas, wo sie nicht schreiben dürfen. Ein sudo -u mcpanel pnpm build scheitert deshalb an EACCES. Gebaut wird als root, und danach muss .next dem Panel gehören, weil next start dort seinen Cache schreibt. Das Skript macht beides in der richtigen Reihenfolge.
Nach jedem Kernel-Update kontrolliert neu starten. Ein neuer Kernel ohne passendes ZFS-Modul heißt: Nach dem Neustart ist der Pool nicht da, und kein Server startet. Deshalb nicht blind automatisch neu starten lassen, sondern nach dem Reboot einmal zpool status ansehen.
Das eine, was noch fehlt. Die Snapshots liegen auf derselben SSD wie die Welten. Sie fangen ab, was täglich passiert — Griefing, ein kaputtes Plugin, ein versehentliches /kill @a. Stirbt die Platte, sind sie mit weg. Der nächtliche zfs send auf die NAS ist noch von Hand einzurichten; der Weg steht im Host-Runbook. Richte ihn ein, bevor der erste fremde Nutzer einen Server bekommt.

Wenn es klemmt

SymptomUrsache und Abhilfe
SSH fragt nach einem Passwort Der Schlüsselimport im Installer hat nicht gegriffen. Mit Passwort anmelden, dann vom Mac aus ssh-copy-id BENUTZER@IP. Prüfen, dass es passwortlos geht, bevor das Setup-Skript läuft.
Permission denied beim Skript sudo bash setup.sh statt ./setup.sh — dann ist das Ausführbar-Bit egal.
„Keine freie Platte gefunden" Du hast im Installer den geführten Weg erwischt, die Platte ist voll vergeben. Prüfen mit sudo vgs und sudo sgdisk -p /dev/nvme0n1. Ist wirklich nichts frei: verkleinern oder neu installieren.
Panel antwortet nicht journalctl -u mc-panel -n 50. Meist fehlt ein Wert in /opt/mc-saas/app/.env — die Anwendung prüft ihre Umgebung beim Start und sagt, welcher.
Kein Zertifikat Caddy erreicht Let's Encrypt nicht oder der DNS-Eintrag zeigt woandershin. Erst dig +short panel.neuhauser.app gegen curl api.ipify.org halten, dann die Caddy-Logs lesen.
Server startet, ist aber nicht erreichbar sudo docker ps — läuft der Container? Dann curl -s localhost:8080/routes: Steht die Adresse in der Routing-Tabelle des mc-routers? Fehlt sie, hilft ein Neustart des Servers im Panel, der trägt sie neu ein.
OOM-Kills im Journal zfs_arc_max prüfen: grep c_max /proc/spl/kstat/zfs/arcstats. Der Cache muss gedeckelt sein, sonst nimmt er den JVMs den Speicher weg.

Wirklich ganz ohne Bildschirm installieren

Geht — mit autoinstall. Auf den Stick kommt neben dem ISO eine user-data mit der kompletten Antwortliste, der Installer läuft ohne Rückfrage durch. Der Haken: Wenn etwas nicht passt, siehst du nichts. Kein Bild, kein SSH, keine Meldung — nur eine Maschine, die nicht hochkommt. Für die erste Installation auf unbekannter Hardware ist das der schlechtere Weg. Wenn du es trotzdem willst, sag Bescheid, dann schreibe ich dir die user-data passend zur Partitionierung aus Schritt 06.
